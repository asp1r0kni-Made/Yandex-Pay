# Сплит Банк — демо-проект

Оригинальное демо-приложение «цифровой банк»: регистрация по телефону,
вход по коду/биометрии, выпуск виртуальных демо-карт. Свой дизайн,
своя иконка, собственное название — не копия какого-либо существующего
банка или платёжного сервиса.

⚠️ **Это учебный/демо-проект.** Карты в нём — не настоящий платёжный
инструмент (для реального выпуска карт нужна банковская лицензия и
партнёр-эквайер/процессинг). SMS-коды в деморежиме просто возвращаются
в ответе API (`debug_code`), т.к. бесплатного SMS-провайдера "из коробки"
нет — подключите своего перед реальным использованием.


## 1. Backend

```bash
cd backend
pip install -r requirements.txt
python app.py
# сервер поднимется на http://localhost:8000
```

Эндпоинты:
- `POST /auth/register` — регистрация по телефону
- `POST /auth/request-code` — запросить код входа
- `POST /auth/verify` — подтвердить код, получить JWT
- `GET /cards` — список карт (нужен заголовок `Authorization: Bearer <token>`)
- `POST /cards/issue` — выпустить новую виртуальную карту
- `POST /cards/{id}/freeze` — заморозить/разморозить карту

База данных — файл `splitbank.db` (SQLite), создаётся автоматически.

Чтобы подключить реальную отправку SMS — впишите вызов своего провайдера
в функцию `send_sms_code()` внутри `app.py`.

## 2. Мобильное приложение (Flutter)

### Первая настройка

```bash
cd mobile
flutter pub get
./bootstrap_android.sh   # сгенерирует android/ и наложит наши файлы
```

### Укажите адрес своего backend

Откройте `lib/services/api_service.dart` и замените:

```dart
static const String baseUrl = "http://10.0.2.2:8000"; // адрес для Android-эмулятора
```

на реальный адрес вашего развёрнутого сервера (например, после деплоя
на любой бесплатный хостинг Python — Render, Railway, Fly.io и т.п.).

### Укажите свой GitHub-репозиторий для автообновлений

Откройте `lib/services/update_service.dart`:

```dart
static const String githubOwner = "YOUR_GITHUB_USERNAME";
static const String githubRepo = "splitbank";
```

Замените на свои значения — именно отсюда приложение будет брать
последний релиз для автообновления.

### Запуск для разработки

```bash
flutter run
```

### Сборка APK вручную

```bash
flutter build apk --release
# файл появится в build/app/outputs/flutter-apk/app-release.apk
```

## 3. Автоматическая сборка и релизы (GitHub Actions)

В репозитории уже есть `.github/workflows/build.yml`. Чтобы собрать APK
и опубликовать релиз:

1. Залейте проект в свой репозиторий на GitHub.
2. Создайте и запушьте тег версии:
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
3. GitHub Actions автоматически:
   - сгенерирует Android-каркас (`flutter create`),
   - наложит кастомные файлы из `android_overlay/`,
   - соберёт `splitbank-v1.0.0.apk`,
   - опубликует его как GitHub Release.

## 4. Как работает автообновление

Файл `lib/services/update_service.dart`:

1. При запуске приложение запрашивает последний релиз через публичный
   GitHub API (`/repos/{owner}/{repo}/releases/latest`).
2. Сравнивает версию релиза с текущей версией приложения.
3. Если есть более новая версия — показывает диалог, по согласию
   скачивает `.apk` из релиза и открывает системный установщик.
4. Пользователю нужно один раз разрешить "Установку из неизвестных
   источников" для этого приложения (Android сам покажет такой запрос
   при первой попытке установки — это системное ограничение Android,
   обойти его нельзя и не нужно).

Таким образом новые версии ставятся поверх старых без удаления данных,
и пользователю не нужно заново ставить APK вручную — только подтвердить
системный диалог установки.

## 5. Что нужно доработать перед реальным использованием

- Подключить настоящего SMS-провайдера вместо `debug_code`.
- Разместить backend на хостинге с HTTPS (сейчас пример на http для разработки).
- Если планируется реальный выпуск платёжных карт — потребуется
  лицензированный партнёр (банк-эмитент/процессинг), это не делается
  "одним файлом" по регуляторным причинам.
- Подписать релизный APK собственным ключом (сейчас используется
  debug-подпись Flutter по умолчанию — для Google Play потребуется
  настроить `key.properties` и подпись в `android/app/build.gradle`).
